# 워커 브리프·검증 템플릿

> 오케스트레이터 판단 패턴을 증류해 박제. 머리가 Fable 이든 Opus 든 그대로 적용한다.
> 참조 방식 = just-in-time(위임 **직전에만** 읽음 — fable-mode.md 는 포인터만 갖는다).

## 1. executor(구현) 브리프 골격 — 6요소 전부 없으면 보내지 마라
```
[안전 한계: 크림 API 호출 허용량 · 보관판매 POST 금지 여부 · DB write 여부 명시.
 금지면 "절대 금지" 문구를 그대로 쓴다]
과제 1줄 → 배경(왜, 실측 근거) → 무엇을·어디를(파일 경로·함수명까지) →
하지 말 것(스코프 밖 명시 — 강한 모델일수록 시키지 않은 것까지 한다) →
검증 기준(테스트 PASS 출력·재현 명령 — "증명 방식"을 지정) →
커밋 규칙(targeted add · 메시지 골자) + 실패 2~3회 시 중단·상황 보고
```
- 픽스처·선례가 디스크에 있으면 **절대 경로**로 지목한다(재조사 방지 = 토큰·안전 둘 다).
- 병렬 executor 가 코드 write 면 **worktree 격리** + "메인 트리 접근 금지" 명시.
  기본은 **순차** — 수정 권한 병렬은 방향 상실을 부른다(`feedback_parallel_scouts`).

## 2. explorer(조사) 브리프 골격
```
[read-only 명시 + 크림 API 호출 상한 N회 · retry 0 · 딜레이 1~2초]
목표 1줄 → 방법 힌트(도구·경로 패턴·재사용할 파서 — "수정 금지") →
엄격 규칙(정확 매칭·억지 금지·없으면 "없음" 그대로) →
돌려줄 것(필드 목록 — 판단 말고 사실만) → 훅 DENY 시 우회 말고 차단문 그대로 보고
```
- 소싱처 검색 함정을 명시한다(예: 무신사 SKU ≠ 크림 모델번호 — 상품명에서 품번 추출해야 함).

## 3. 위임 전 blind-spot pass (30초 자문)
① 이 브리프에서 워커가 **내가 안 정해준 것**을 뭘 임의로 정하게 되나? (그 지점이 사고 지점)
② 실패했을 때 워커가 **우회·확장**할 유인이 있나? (있으면 금지 문구 추가)
③ 결과를 내가 **무엇으로 검증**할 건가? (증거 형식을 브리프에 미리 요구)

## 4. 결과 검증 체크리스트 (검증은 머리 몫)
- 증거 우선: 테스트 출력·diff·커밋 해시·DB 재조회 결과를 **직접 재확인**(워커 요약만 믿지 않기).
- **반박자 배선**: 크림 호출·보관판매·수익 계산 인접 산출물은 작업자가 자기채점 못 하게
  별도 검토(`profit-analyzer`·`code-reviewer` 또는 Codex 적대검증).
- 예상 밖 결과면 재작업 지시 전에 **"왜 그렇게 판단했나" 먼저 질문** — 브리프·훅 결함이 드러난다.
- 워커의 숫자 주장은 출처 등급 표기를 요구한다(공식/실측/스니펫/단일주장). 스니펫은 재확인 대상.
  ⚠️ **라이브 관측 없는 수치는 반려**한다 — 증거 게이트가 나에게도 걸린다.

## 5. 라우팅 경제 (재확인된 원칙)
- 단순 작업에 병렬 fan-out = 토큰 소각. 1~5파일 응집 수정·단순 조회는 머리가 직접.
- 조사·회수는 최저가 워커(Haiku), 구현은 Opus, 판단·설계·검증만 머리.
- 캐시 경제: 세션을 길게 이어 쓴다(캐시 할인). 잘게 끊지 않는다.
