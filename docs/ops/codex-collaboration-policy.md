> Codex(OpenAI CLI, ChatGPT Plus 인증)를 크림봇 워크플로의 **독립 적대검증관·조언자**로

## 🔒 대전제 (불변 — 안전 경계선)

1. **Codex = 검토관·조언자, 집행자 아님.** 크림 API 호출 · DB write · 소싱처 fetch ·
   Discord 발송 **직접 실행 절대 금지**. `-s read-only` 로만 실행하고
   `--dangerously-bypass-*` 계열 플래그는 쓰지 않는다.
2. **판정은 항상 사장께 요약 보고.** 조용히 흡수하지 않는다(사장 감시 창 유지).
3. **수정 권한 분리**: Codex 지적으로 **코드·테스트·문서는 Claude 가 바로 수정**.
   단 보관판매 POST · 실계정 작업 · 봇 기동/중지는 사장 GO.
4. **트리거는 수동이다.** ChatGPT Plus 계정이 하나라 **구매대행 프로젝트와 한도를 공유**한다.
   크림봇은 Stop 훅 자동 큐잉을 배선하지 않는다 — 사장이 부를 때만.
   (구매대행 쪽 정책 문서에 "크림봇 무접촉" 문구가 있는데, 그건 2026-07-24 이 결정으로
   무효다. 그쪽 레포는 이 세션에서 건드리지 않았다 — 사장이 그 세션에서 정정.)
5. **프로젝트 분리**: `-C <크림봇루트>` + `--ignore-user-config` + `-c mcp_servers={}` 로
   다른 프로젝트 설정·MCP 를 상속하지 않는다. env 는 allowlist(`src/ops/codex_child_env.py`)
   통과분만 — Discord/무신사/크림 자격증명은 자동 차단된다.
6. **비용 = Plus 한도**(현금 아님). 매 변경마다가 아니라 **체크포인트에서만**.

## 등급 정책 — "일상은 싸게, 실사고 위험 구간의 지능은 낮추지 않는다"

OpenAI 공식 역할 구분을 따른다: **Terra = 일상 기본**, **Luna = 가벼운 대량 작업**,
**Sol = 품질·추론 깊이가 가장 중요한 작업**.

크레딧(1M 토큰, 입력 / 캐시입력 / 출력) · Plus 5h 로컬 메시지:

| 모델 | 크레딧 | 5h 메시지 | 역할 |
|---|---|---|---|
| Sol | 125 / 12.5 / 750 | 15~90 | 최고 품질 · 복잡 판단 |
| Terra | 62.5 / 6.25 / 375 | 20~110 | 일상 기본 · 성능/비용 균형 |
| Luna | 25 / 2.5 / 150 | 50~280 | 빠른 단순 작업 · 대량 처리 |

같은 토큰량 기준 **Terra 는 Sol 의 1/2, Luna 는 Sol 의 1/5** 크레딧이다.
effort 별 토큰 배수는 공식 미공개이므로 `Luna/high > Sol/low` 같은 교차 성능을 단정하지
않고 **역할·실위험**으로 승격한다.

**규칙**:
- **Luna 에게 최종 판단을 맡기지 않는다** — 열거·breadth 전용.
- 매번 Luna→Terra→Sol 을 다 돌리지 않는다. 기본 Terra 1회, **중대 지적이나 불확실성이 있을 때만**
  그 finding 을 Sol 로 승격. S등급은 중간 단계 없이 Sol/xhigh.
- `sol/max` 는 **자동 경로에 없다**(`test_max_effort는_자동경로에_없다` 로 고정).
  xhigh 로도 결론이 안 날 때 사람이 1회만 지정한다.
- 전체 repo 대신 **diff·지목 파일만** 주고, 출력은 실제 반례 최대 5건으로 제한한다
  (비용은 모델뿐 아니라 입력·도구결과·추론·출력에 좌우된다).

## 3가지 모드

### ① 검증 (Verify)
끝낸 코드/변경을 버그·보안·엣지케이스로 적대검토.
부를 만한 시점: 안전 경계 변경(S등급 경로) · 다중 파일 리팩터 · 신규 파서/스크립트 ·
배치 작업 마무리 · 보관판매 관련 작업 직전.
→ `python scripts/codex_collab.py verify`

### ② 의논 (Consult)
2개 이상 접근이 갈리거나 구조 결정 전 제2의견. **결정은 Claude/사장**, Codex 는 입력이다.
→ `python scripts/codex_collab.py consult "A vs B — 근거와 함께 추천"`

### ③ 협업 (Collaborate)
한 번에 안 풀리는 난제를 각자 시도하고 상호 비평.
→ `python scripts/codex_collab.py collab "…"`

### ❌ 안 부르는 것 (한도 아낌)
문서·메모만 변경 · 한 줄 오타 · read-only 진단/조회 · 일회용 probe 스크립트.
→ 게이트가 **N등급**으로 판정해 자동으로 호출하지 않는다.

## 🎯 수렴 원칙 — 무한 반복 금지

Codex 는 **적대검토관·조언자이지, 모든 지적을 반드시 반영해야 하는 권위가 아니다.**
검증이 라운드마다 새 엣지를 낳아 끝나지 않는 걸 막는다.

**수용/거부 판단**:
- ✅ **수용** = ① Codex 가 **진짜 내 실수/버그를 잡았을 때**, 또는
  ② **내가 봐도 더 나은 게 맞을 때**(독립 공감).
- ❌ **거부(반드시 근거 1~2줄과 함께 보고)** =
  ⓐ 지적이 **명시 요구·설계와 배치**
     (크림봇 예: 거래량 게이트 1 · 47k 전체 타겟 · 푸시 단일 트랙 · `tier2_monitor` 존치 —
      전부 `feedback_settled_decision_lock` 대상이다)
  ⓑ **이론적·legacy 엣지로 실 리스크 미미**
  ⓒ **합리적으로 동의 안 됨**.
  **조용한 무시 금지** — 왜 거부하는지 명시한다.

**라운드 바운드**:
- 핵심(안전·정확성 실버그)이 봉합되면 **멈춘다**. 남은 게 (a) 근거 갖고 거부할 것 또는
  (b) deferred(문서화된 차기 GO) 뿐이면 **더 안 돌리고 수렴 보고**.
- 목표 = **"실 리스크 처리 완료"** 이지 "Codex 무지적 0" 이 아니다.
- **봉합 후 재검증은 1회**(수렴 라운드) → 새 REAL 없으면 종료.
  근본 아키텍처급 결함은 **별건으로 분리**한다.
- 보고 형식: **수용 N / 거부 N(각 사유) / 수렴 근거 / deferred 목록.**

## 호출 위생 (사고 방지)

- **출력을 `> /dev/null` 로 버리지 않는다.** `reports/codex/codex_<snap>.raw.log` 에
  returncode/stdout/stderr 를 항상 남긴다.
  (원본 사고: 한도초과 에러가 즉시 떴는데 못 보고 51분 헛대기 + 사장에게 틀린 설명.)
- **호출 전 한도 프로브 금지** — 확인용 메시지 자체가 한도를 쓴다. 실제 호출 실패로 감지한다.
- **호출 전 `plan` 을 먼저 돌려 등급을 보고**한다(Codex 호출 0, 한도 0).
- **한도 초과 = fail-open**: 멈추지 말고 자체 검증(재현 시나리오 + targeted test)으로 진행하고
  "검증 밀림 N건"을 보고한다. 다음 호출 때 `drain` 으로 **현재 상태로** 처리한다.
- 미검증 상태는 보관판매 POST · 실계정 작업의 GO 근거가 될 수 없다.
- 타임아웃 기본 1800s(xhigh 는 900s 를 넘는다는 실측). `KREAM_CODEX_TIMEOUT` 로 조절.
